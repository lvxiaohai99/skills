# 把 raw.md 整理成标准文章

脚本只负责「抓下来、下图片、去掉明显的网页零件」。`raw.md` 里仍可能有：

- 推荐阅读、关注作者、版权套话、目录残留
- 标题层级乱跳（突然来一个 `####`，或正文里重复了一遍大标题）
- 表格被拆碎、列表符号不统一
- 装饰性空行、零宽字符、`​` 占位
- 和正文无关的小图标（脚本会尽量删，漏网的在这一步补刀）

这一步由模型完成。目标：**读起来像一篇干净的技术文档**，不是网页导出残片。

## 必须保留

- 原文的技术内容、步骤、结论、注意事项
- 所有**正文配图**（架构图、截图、流程图）。路径写成 `./images/img_xxx.png`，不要改成网上的地址，也不要凭空编一张图。文件夹名里不要留 `？` `?` `：`，否则预览会把图片地址截断。
- 所有代码块：语言标注、缩进、换行都不要改。吃不准语言时，保持脚本标的那个
- 文首的原文链接（`> 原文链接: ...`）；公众号再保留 `> 公众号: ...`

## 必须丢掉

- 广告、关注/订阅/点赞/打赏/在看、相关推荐、评论区
- 公众号开头的「点击上方星标/关注」、文末「往期推荐」、二维码、赞赏码
- 「觉得不错就收藏」「版权归作者所有，转载请联系」这类套话（文首一条原文链接已经够了）
- 和标题完全重复的开头大标题
- 空的图片、裂图占位、明显的表情/头像/二维码
- 网页目录（如果正文标题已经能当目录）

拿不准「这是不是正文」时：**留下**，并在交付时用一句话告诉用户你留了什么。

## 标准 Markdown 长什么样

```markdown
# 文章标题

> 原文链接: https://...

一句话说明这篇文章在讲什么（可从原文开头改写，不要发明原文没有的结论）。

## 背景 / 问题

...

## 做法

### 小节标题

正文段落。

![有意义的替代文字](images/img_001_xxxx.png)

```bash
# 命令保持原样
```

## 注意点

- ...
```

具体章节名跟着原文走，不要强行套上面的「背景 / 做法」。上面只是版式样例。

## 整理时的手势

1. 先通读 `raw.md`，标出：标题、配图、代码、可删的套话。
2. 只写一个一级标题 `#`，下面用 `##` / `###`，不要跳级。
3. 列表统一用 `-`；有顺序的步骤用 `1. 2. 3.`。
4. 表格补齐表头和对齐，不要把表格拆成一堆加粗碎片。
5. 图片 `alt` 写成「这张图在说明什么」，不要只写 `image`。
6. 不要把几篇无关文章揉成一篇。用户明确说「合成一篇笔记」时才合并，并在文首列出所有原文链接。
7. 写完后对照 `raw.md`：代码块数量不应变少；正文配图不应失踪。

## 交付文件

每篇文章目录里：

| 文件 | 谁写的 | 能不能覆盖 |
|------|--------|------------|
| `raw.md` | 脚本 | 不要覆盖，方便对照 |
| `images/` | 脚本 | 不要改文件名 |
| `article.md` | 模型整理后的标准稿 | 这是给用户看的成品 |

多篇时再在输出目录根下写一份 `README.md`：每篇的标题、链接、成品路径、图片张数。
