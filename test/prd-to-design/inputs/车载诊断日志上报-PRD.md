# 车载诊断日志上报（样例 PRD）

| 项 | 内容 |
| --- | --- |
| 产品 | 车载诊断助手 |
| 版本 | v0.3 草稿 |
| 作者 | 产品（样例） |
| 平台 | 车机 Android + 车云 |

## 1. 背景

售后排查 ECU 故障时，司机说不清当时情况，4S 店无法拿到车辆侧日志。需要让司机在安全停车后，一键把最近一段时间的诊断日志发到云端，供售后工程师下载分析。

## 2. 目标

- 司机 3 步内完成一次上报（入口 → 确认 → 看到结果）。
- 售后能在工单里看到对应车辆的数据包，并下载。
- 不能把 VIN 以外的个人身份信息、精确 GPS 明文传到云端。

成功标准（首期）：实验室弱网（丢包 10%）下，10MB 以内数据包最终能传完；失败时司机能看懂原因。

## 3. 角色

| 角色 | 诉求 |
| --- | --- |
| 司机 | 停车后一键上报，知道成功还是失败 |
| 售后工程师 | 按车牌/VIN + 时间找到包并下载 |
| 车云服务 | 收包、鉴权、存储、提供下载 |

## 4. 场景

1. 车辆报故障灯，司机在 P 档停车，从车机「诊断助手」点「上报日志」。
2. 系统收集最近 30 分钟（若不足则收集现有全部）的诊断日志，脱敏后上传。
3. 售后在门户用 VIN 搜索，下载 zip。

## 5. 功能需求（产品描述）

### 5.1 发起上报

- 仅在 P 档或驻车状态允许发起；行车中入口置灰，文案：「请停车后上报」。
- 二次确认，说明将上传诊断数据、大约耗时与流量（可给估算，不准也行）。
- 同一时间只允许一个进行中的上报任务。

### 5.2 采集与打包

- 日志范围：诊断模块本地文件，最近 30 分钟；单包上限 20MB，超出则按时间从旧到新丢弃直到满足上限，并在包内 manifest 记录截断。
- 打包为 zip，内含 manifest.json（起止时间、是否截断、软件版本）。

### 5.3 隐私

- 去掉精确 GPS、手机号、账号 token。VIN 保留。
- 具体字段表「后续补充」。

### 5.4 上传

- 优先 Wi-Fi；无 Wi-Fi 时用蜂窝，需再确认一次（流量提示）。
- 弱网要能传完：失败自动重试。重试次数产品未定。
- 显示进度（百分比即可）。
- 成功/失败要有明确结果页。失败可手动再试。
- **上传协议、云端 URL、鉴权方式后续与云平台对齐，本 PRD 暂不指定。**

### 5.5 售后门户（首期最小）

- 列表：VIN、上报时间、包大小、状态。
- 仅售后角色可下载。
- 不做在线解析、不做自动出维修建议。

## 6. 非功能

- 上报过程不得阻塞仪表等关键进程（车机侧低优先级）。
- 本地最多保留 3 个未成功任务，更早的失败任务删除并告知。
- 包在云端保留 90 天。
- 实验室：10MB 包在 10% 丢包下最终成功。

## 7. 范围外

- 远程刷写、远程诊断会话、实时推流。
- 自动生成维修方案。
- 多语言（首期仅简体中文）。
