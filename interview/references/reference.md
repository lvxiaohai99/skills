# 面试小助手：出题、参考答案与领域技能原则

只在写「领域核心岗位技能」和面试题（含参考答案）时阅读本文件。

## 一面 vs 二面

| | 一面 | 二面 |
|---|---|---|
| 目标 | 人岗匹配、简历是否属实、栈是否够深 | 能否独立扛事、架构判断、成长空间 |
| 题型 | 原理、对比、排障、项目还原 | 设计、取舍、事故、带人/协作、演进 |
| 时长感 | 单题 3~8 分钟 | 单题 8~15 分钟，可展开 |
| 通过信号 | 能讲清自己写过的代码和选型 | 能讲清为什么、备选方案、复盘 |
| 参考答案侧重 | 正确概念 + 本项目合理操作路径 | 权衡框架 + 决策标准 + 复盘 |

一面至少覆盖：

1. 简历里最核心的一门语言/框架原理
2. 其存储或中间件（有则问）
3. 一段项目的「你具体做了什么」
4. 一道与日常工作相关的排障或编码思路（口述即可，不要求当场写代码除非用户要求）

二面至少覆盖：

1. 最大复杂度项目的架构与取舍
2. 性能 / 稳定性 / 数据一致性 三者择其与简历相关者
3. 协作或 ownership（需求不清、线上故障、跨团队）
4. 结合「未来演进方向」的一道开放题

## 职级调难度

- **初级（约 0~2 年）**：问「做了什么、怎么做的」；少问大规模架构。参考答案给标准步骤即可。
- **中级（约 2~5 年）**：问选型原因、坑、监控与回滚。参考答案要含「为什么这样选」。
- **高级 / 专家**：问容量规划、多方案对比、组织影响、技术债策略。参考答案要含备选方案与取舍标准。

年限只是线索。带人、跨端、从 0 到 1、对结果负责，可以提高一档。

## 简历锚点

每题「简历锚点」写成：`[公司/项目] + [技术或职责原句浓缩]`。

反例：`考察 Java 基础`（没有锚点）。
正例：`锚点：XX 电商订单服务，简历写「Spring Cloud + Redis 削峰」`。

## 参考答案怎么写

目标：面试官一边听候选人说话，一边扫「参考答案 / 评分口径」判断过没过。

### 结构（每题都要）

1. **期望要点**：合格线，3～5 条短句（候选人应覆盖的点）。
2. **参考答案**：8～15 行可扫读正文，建议顺序：
   - 一句话结论
   - 关键原理或操作步骤（条理化 1/2/3）
   - **挂回本简历**：用「结合其 XX 经历，合理答法是…」把答案落到他的项目，而不是百科全文
   - 简历没写的数字：写「应能给出量级/测量方法」，不要伪造「当时是 35%」这类假事实
3. **评分口径**：
   - **过线**：听到这些就可以认为「这题过了」
   - **加分**：深度、度量、复盘、备选方案
   - **疑点**：空话、与简历矛盾、全是名词无细节、把别人工作说成自己的
4. **追问参考**：针对追问的短答案（1～3 句），方便连问。

### 文风

- 开头可写：`（对照用，非候选人原话）`
- 用祈使/陈述句给面试官看，不要写成「你应该回答：」的说教长文
- 一面参考答案偏「正确做法」；二面偏「决策框架」，允许多种合理答案，但要写清评价标准

### 反例

- 只有期望要点、没有参考答案正文
- 参考答案大段背书与简历无关的八股
- 把推测写成「候选人做过 XXX（简历未写）」
- 参考答案泄露或鼓励泄露未公开机密配置

## 领域技能三块怎么写

**背景**：用 4~8 句说明该岗位在业务里解决什么问题，候选人路径（例如从业务开发到平台）意味着什么。

**当前的主流技术**：用表格，每行一个该领域面试常问/生产常用的能力。候选人列只允许：

- 已覆盖（简历有证据）
- 部分（用过皮毛或仅名词）
- 缺口（岗位需要但简历没有）

**未来演进方向**：写 3~5 条可追问的方向（例如云原生、可观测性、AI 辅助研发、领域特定方向），每条点出和候选人现状的关系。

不要把「微服务、中台、数字化转型」当万能词，没有简历证据就不要写。

## 常见领域的出题重心（按需取用，不要全抄）

按候选人主栈选一组，再改写成绑定简历的题。

- **后端**：语言并发与内存、API 与数据模型、事务/一致性、缓存与消息、可观测性。
- **前端**：渲染与状态、性能、工程化、组件设计、与后端契约。
- **数据**：建模、调度、质量、数仓分层、分析场景。
- **测开 / QA**：策略、自动化金字塔、环境与数据、质量度量。
- **客户端**：生命周期、性能与包体、发布、原生能力。
- **嵌入式 / 系统软件**：启动与 BSP、驱动与设备树、内存与实时性、OTA/升级回滚、外设与媒体链路、交叉编译与量产。
- **车载座舱 / Android Native**：HAL/Framework、Camera/Display/Input、虚拟化与双系统、启动与稳定性、车载通信。
- **AI / LLM 应用**：评测、RAG/工具调用、幻觉与安全、成本与延迟。

## 禁止

- 与岗位无关的智力题、偏题算法（用户明确要求算法岗除外）。
- 原题照搬网络热门「八股」且与简历无关。
- 要求候选人泄露前雇主未公开的机密实现细节；问法用「你当时怎么设计」而非「把公司内部配置说出来」。
- 只出题不给参考答案 / 评分口径。
