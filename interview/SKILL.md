# 面试小助手

根据候选人简历，整理技术画像并生成一面、二面核心问题。输出必须结合这份简历，禁止套用与经历无关的通用题库。

`$SKILL_DIR` = 本 skill 根目录（本文件所在目录）。

## 何时启用

用户提供简历（粘贴、附件、或指定路径），或提到：面试小助手、简历评估、一面、二面、面试题。

## 工作流程

按顺序执行，缺一步就停下来补信息：

```
任务进度:
- [ ] 1. 拿到完整简历文本
- [ ] 2. 整理技术栈 / 核心能力 / 工作经历表
- [ ] 3. 按领域写核心岗位技能（背景 / 主流 / 演进）
- [ ] 4. 生成一面 5~7 题、二面 5~7 题
- [ ] 5. 按模板输出，并保存报告
```

### 1. 读取简历

支持扩展名：`.pdf` `.docx` `.doc` `.xlsx` `.xls` `.md` `.markdown` `.txt` `.html` `.htm` `.csv`

**有文件路径时**，先跑提取脚本（不要自己猜二进制内容）：

```bash
# 首次或缺依赖时
python3 -m venv "$SKILL_DIR/.venv"
"$SKILL_DIR/.venv/bin/pip" install -r "$SKILL_DIR/requirements.txt"

PYTHONIOENCODING=utf-8 python3 "$SKILL_DIR/scripts/extract_resume.py" "<简历路径>"
```

已有可用的 Python 环境且装过依赖时，可直接：

```bash
PYTHONIOENCODING=utf-8 python3 "$SKILL_DIR/scripts/extract_resume.py" "<简历路径>"
```

读写报告时一律使用 **UTF-8**（无 BOM 亦可）。核对内容时用编辑器或 `python3` 读文件，不要用未设 UTF-8 的终端命令判断是否乱码。

脚本会打印 `===RESUME_META===` 和 `===RESUME_TEXT===`。

- `chars < 200` 或 `warnings` 含 `low_text`：可能是扫描件/图片 PDF。请用户改发 Word、Markdown，或可复制文本的 PDF。
- 用户直接粘贴文本：跳过脚本，以粘贴内容为准。
- 用户没给文件：在当前工作目录的 `简历/` 下找；找不到则请用户提供路径或粘贴。

多份简历时，一次只分析一份；用户没指定就问选哪份。可一次处理多份时，每份各出一份报告。

### 2. 整理候选人画像

从简历中抽取，不要编造。写「简历未写」而不是猜测。

| 抽取项 | 要求 |
|---|---|
| 技术栈 | 按语言 / 框架 / 中间件与存储 / 云与工程化 分组；标出熟练 vs 仅提及 |
| 核心能力 | 3~6 条，用成果说话（带规模、指标、职责），不要空泛形容词 |
| 工作经历 | **必须用表格**，见下方模板 |

推断职级（初级 / 中级 / 高级 / 专家）只用于调题难度，并在报告里写清依据（年限、带人、架构职责）。

### 3. 领域核心岗位技能

先判断主领域（如 Java 后端、前端、数据、测开、客户端、嵌入式、AI 应用等）。然后写三块，都要贴合**这个人的栈和经历**，不要写放之四海皆准的百科：

1. **背景**：这个岗位为什么需要这些能力；和候选人路径怎么对上。
2. **当前的主流技术**：该领域现在面试/生产里常见的技术与实践；标出候选人已覆盖 / 缺口。
3. **未来演进方向**：该领域 2~5 年常见演进；候选人可追问的成长点。

细节原则见 [references/reference.md](references/reference.md)。

### 4. 出题规则

- **一面 5~7 题**：验证简历真实性 + 技术栈深度 + 1 道项目细节。偏基础、原理、动手。
- **二面 5~7 题**：架构取舍、复杂问题、ownership、领域演进。偏设计、权衡、影响力。
- 每题必须能指回简历里的某段经历或某项技术，写在「简历锚点」。
- 难度匹配职级：初级少八股堆砌，高级少「说说什么是 REST」。
- 不要问简历里完全没出现、也与目标岗位无关的技术。
- 题目结构固定为：题干 / 考察点 / 简历锚点 / 期望要点 / 追问（1~2 个）。

出题质量标准见 [references/reference.md](references/reference.md)。完整示例见 [references/examples.md](references/examples.md)。

### 5. 输出与保存

聊天里用下面模板（Markdown）。同时把全文保存为 UTF-8 `.md`：

| 优先级 | 保存位置 |
| --- | --- |
| 用户指定了输出路径/目录 | 按用户指定 |
| 当前目录存在 `报告/`（或正在测 `test/interview/`） | `报告/<简历主文件名>.md` 或 `test/interview/outputs/<简历主文件名>.md` |
| 其它 | 在 cwd 建 `报告/`，写入 `报告/<简历主文件名>.md` |

文件名与简历主文件名一致（不含扩展名）。已有同名报告则覆盖。粘贴文本、没有源文件名时，用候选人姓名：`<姓名>.md`。

| 简历 | 报告 |
| --- | --- |
| `简历/张三.pdf` | `报告/张三.md` |
| `test/interview/inputs/李四-嵌入式.md` | `test/interview/outputs/李四-嵌入式.md` |

## 约束

- 用简体中文，表格对齐，语气像给面试官的内部笔记：短句、可执行。
- 不评价外貌、年龄歧视、婚育等无关项；不编造未出现的公司、项目、指标。
- 用户只要其中一块（例如「只要一面题」）时，仍先做完画像中的技术栈与经历表，再出题，避免题目悬空。
